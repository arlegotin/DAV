# Dependency-aware verification: local result

**NO_GO for the extra dependency-aware mechanism in this local setting. A simpler test-first workflow was useful in the fresh pilot.** The one permitted replacement pilot completed: eight correct and 16 incorrect natural proposals, all mechanically valid. Public tests separated all 24 correctly on the specified evaluator. Model reviews added cost and rejected every correct proposal or returned UNKNOWN. The unchanged M2 gate stopped further collection.

This is a substantive evidence-menu failure, **not a RAM, disk-space, runtime-budget, or GPU shortage**. It does not show that dependency-aware verification is generally useless. The original pilot remains separately **INCONCLUSIVE**: three correct, 21 incorrect, with incomplete public tests accepting three wrong patches. Neither pilot is a held-out success claim.
